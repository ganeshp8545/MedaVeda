# Content upload and publishing verification

## Staging checkpoint — 2026-10-18

No isolated staging credentials were available. Authorized admin create/edit/upload/publish/unpublish, browser refresh, duplicate/lost response, unauthorized upload, incorrect file, and 1 MB/10 MB/near-50 MB valid PDF cases are **BLOCKED**. Mobile hierarchy, free YouTube playback, verified MCQ result, offline retry, raw private URL denial, paid/free-preview signing, and refund denial are **BLOCKED**. The current upload function buffers multipart bytes, a second contiguous body, a `File` and its byte array before PDF parsing; near-50 MB runtime memory and request limits are **NOT VERIFIED** and must be measured on staging before promising that size. [Supabase's hosted Edge limit is 256 MB memory and 2 seconds of active CPU per request](https://supabase.com/docs/guides/functions/limits); [Storage's global limit also applies in addition to the bucket's limit](https://supabase.com/docs/guides/storage/uploads/file-limits). These published limits do not prove that this implementation can process a 50 MB PDF.

There is no malware scanner in `upload-note-pdf`. Structural PDF parsing catches malformed files, but a valid PDF may contain harmful links, embedded content, or exploits in downstream readers. The upload surface is restricted to authenticated admins, optionally AAL2 by `admin_settings`, and service-role Storage writes after the pending migration; these controls reduce who can submit a file but do not scan it. [Google Play's policy applies to content an app displays or links to](https://support.google.com/googleplay/android-developer/answer/18258653?hl=en), but that policy does not prescribe a specific PDF antivirus product or scanning architecture. This is an inference from the policy text, not a compliance ruling. Decide whether launch policy requires antivirus/content disarm. Options include a private quarantine bucket with asynchronous scanner and promotion only after a clean verdict, or a dedicated scanning service before the note is published. Until then, restrict uploader accounts, require MFA, use trusted source PDFs, keep drafts inactive pending review, log uploads, and retain the residual risk explicitly.

The read-only inventory [note_upload_reconciliation_readonly.sql](../../supabase/tests/note_upload_reconciliation_readonly.sql) classifies ledger rows by current note references and object existence. It never deletes or changes a row. A lost save response may already have committed a note; compare note ID, exact URL and object path, review replacement history and concurrent edits, then retain every possibly referenced object. No automated garbage collection is authorized by this inventory. The inventory itself is **BLOCKED** until staging exists.
