## Architecture and data flow

`admin-panel/` is React 19, Vite, Supabase JS and client-side routes protected by `am_i_admin()`. Admin pages call services that write directly to public PostgREST tables. Notes upload directly to the `notes` Storage bucket; `notes.pdf_url` stores a URL-shaped object identifier. `mobile-app/` is Expo 57 / React Native with Supabase repositories and an offline SQLite sync queue. The website is generated static HTML in `website/` and retains its separate Razorpay path. `supabase/migrations/` contains 51 SQL files; `supabase/functions/` contains Edge Functions for paid notes, Play purchases, refunds, catalog sync, account deletion and website payments. `.github/workflows/ci.yml` builds admin/mobile/site and has Deno, PostgreSQL and secret-scan jobs.

Content path: admin session → `am_i_admin()` and table/storage RLS → `notes`, `videos`, `quiz_tests` → mobile repositories. Paid PDF path: `get-note-url` → `user_can_access_note` → service-role signed URL with 120-second expiry. Videos are YouTube URLs and are free for signed-in, nonblocked users under `20261016090000_free_video_access.sql`; the admin does not upload video bytes. Quiz tests are subject-scoped, with 20 inline JSON questions; scores are calculated on the device and synced to `quiz_scores`.

Play path: `expo-iap` → `create-play-order` → `verify-play-purchase` → Google Publisher status validation → `settle_play_purchase` → entitlement. `play-payment-worker` consumes and reconciles transactions and handles void/refund reversal. Product price editing has a catalog queue and admin sync status in the current dirty worktree; its remote deployment and queue health were not verified. `app.config.js` enforces the Play provider for production/internal-testing profiles; website Razorpay is separate.
