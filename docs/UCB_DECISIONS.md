# MedVeda UCB decisions and release gates

Updated 2026-10-12. These decisions record implementation choices from [the UCB plan](UCB_PLAN.md). They do not certify that the app or Console is ready for release.

| Area | Decision | Reason / remaining check |
|---|---|---|
| India program | Use India's Play alternative billing with user choice enrollment for `in.medveda.app`. | India is a separate program. Enrollment and app opt-in are manual [Play Console steps](https://support.google.com/googleplay/android-developer/answer/13306652). |
| Tier products | Map each real active server price to an exact one-time Play SKU; consume after verified server grant. | A tier SKU is reused across many note products. Confirm the **live** price inventory and each Play INR price before release. No live inventory was supplied in the repository. [Play consumption guidance](https://developer.android.com/google/play/billing/integrate). |
| Tier seed | Keep `supabase/seed/play_price_tiers.json` empty until the owner supplies the live price query. Validate with `apply-play-price-tiers.mjs`; its apply mode inserts inactive tiers only. | The production database is unavailable in this workspace, so no price is guessed. Each SKU must be checked in Play Console before activation. |
| Price and discounts | Play charges its displayed SKU price without referral discount or partial wallet; Razorpay keeps today's server-side discount and wallet pricing. | India permits different prices across billing systems. Referral qualification after a successful Play purchase remains server-side. [India program FAQ](https://support.google.com/googleplay/android-developer/answer/13306652). |
| Full-wallet unlock | Follow-up, not included in UCB launch. | Current server order cap requires a positive charge; a zero-payment grant needs a distinct, reviewed entitlement and referral policy. |
| Obfuscated IDs | Use deterministic one-way SHA-256 hex identifiers for user and order, checked against Play's verified purchase response. | Google recommends encryption or hashing and limits these fields to 64 characters. Never send email/phone in these fields. [BillingFlowParams](https://developer.android.com/reference/com/android/billingclient/api/BillingFlowParams.Builder). |
| Tier consumption | The backend is authoritative for verification/grant and must ensure consumption is retried after grant. | Consuming makes a tier available for another product and fulfills acknowledgement. A consumed purchase may disappear from `getAvailablePurchases`, so server purchases remain the access source. [Google processing guide](https://developer.android.com/google/play/billing/integrate). |
| Grant implementation | Keep the existing 300+ line Razorpay settlement function intact. Add a separate atomic Play settlement RPC with the same referral anti-farming conditions and cover parity in SQL tests. | A literal shared grant module would require reissuing mature Razorpay settlement logic and risks changing its discount/wallet behavior. This is a deliberate deviation from the original shared-module request; future changes to referral rules must update both RPCs together. |
| External reporting and tax | Owner states the current GST rate is 0%. Use `app_config.gst_rate_percent=0`, snapshot that rate and actual authorized Razorpay amount on each order, and report pre-tax equal to charged amount with tax 0. If the rate changes, apply reviewed tax rules and snapshot the new split; never recalculate old orders. Store stable external transaction ID and reconcile retries before marking reported. | **Release gate:** a successful licensed test report is still required. The 0% configuration is an owner-supplied business fact, not something established by repository code. Report post-discount/wallet amount, not list price. [Backend guide](https://developer.android.com/google/play/billing/outside-gpb-backend). |
| Buyer state | Require the user to select an Indian billing state before Android Razorpay checkout, validate it against Google-accepted administrative-area values, and store it on the order for reporting. `seller_state` stays unset until owner provides it. | **Release gate:** Google's India reporting needs `userTaxAddress.administrativeArea`; do not invent a value or permit this checkout branch without one. [External transaction API](https://developers.google.com/android-publisher/api-ref/rest/v3/externaltransactions). |
| UCB enforcement | Set `app_config.require_ucb_for_razorpay=true` before Android release; the server rejects direct Razorpay order creation without a bound Play user-choice order. Hide non-Android purchase controls in the new app and force old binaries to update with `min_app_version`. | The server cannot trust a client-supplied platform label. The switch defaults false during migration only; leaving it false at release permits a Razorpay-only Android client. The user explicitly allowed non-Android purchase UI to be hidden. |
| Refunds | Queue each processed Razorpay refund by stable refund ID. Report partial refunds with Google's `partialRefund`; report a full refund of the remainder with `fullRefund`. Preserve access after a partial refund and use the existing reversal rules after a full refund. Poll paid Play purchase tokens for voids and revoke access and referral credit. | The queue is retryable and checks Google's current pre-tax balance before resending an ambiguous partial result. A live licensed partial/full refund test is required. [Refund API](https://developers.google.com/android-publisher/api-ref/rest/v3/externaltransactions/refundexternaltransaction). |
| Recovery | Re-verify unresolved Play purchases on app start/login and repeat server settlement idempotently; do not grant while pending. | The Play purchase listener can be missed after process death. [Billing lifecycle](https://developer.android.com/google/play/billing/integrate). |
| Native testing | Use a new EAS Android binary installed from Play internal testing with a licensed India Play tester. | Expo Go cannot host added native IAP code. [Expo guidance](https://docs.expo.dev/develop/development-builds/faq/). |

**Release gate summary:** verified India enrollment and app opt-in; actual live tier inventory and exact Play prices; server tax snapshots at configured 0% and required buyer-selected Indian state; working Google API credentials; a licensed Play-installed test covering Play, Razorpay, cancel/pending, same-tier repeat purchase, reporting and refunds; updated Play Data safety answers and live legal pages.
